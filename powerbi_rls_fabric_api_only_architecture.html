Centralized Power BI RLS Governance — Fabric API Only

Central IT version-controls only RLS. Reports are discovered/validated but never modified. The live semantic model is read first, RLS is merged in memory, and the resulting complete definition is sent back through Fabric updateDefinition.

Existing Power BI Assets

Visualization team remains unchanged
  • Creates and publishes reports normally
  • Owns semantic-model business logic
  • No code-based report development required
Central IT does not modify
Report definition, visuals, measures, tables, relationships, or business logic.

Mandatory Safety Gate Before Any RLS Update

#CheckPurposeFailure action
1Workspace existsPrevent deployment to invalid/moved workspace.STOP
2Configured report existsEnsure project is still active and correctly mapped.STOP
3Semantic model existsEnsure configured target is valid.STOP
4Report uses expected semantic modelVerify report.datasetId == semanticModelId.STOP
5Security contract validRequired tables, columns and relationships referenced by RLS still exist.STOP
6Current model definition retrievedNever deploy RLS using a stale full-model copy stored in Git.STOP
7Non-RLS fingerprint stableDetect visualization-team publication between read and update.STOP / retry
8Post-update role verificationEnsure deployed role matches approved Git state.FAIL deployment
9RLS behavior testValidate effective-user filtering.FAIL / rollback process
Recommended concurrency fingerprint: calculate a hash over all definition parts except definition/roles/*. Re-read just before deployment. If the hash changed, another model publication occurred and the pipeline must rebuild the merge from the newest live definition.

Git ownership principle

Git owns RLS only.
Tables, measures, relationships and report definitions are always sourced from the current live Power BI semantic model when deployment runs.

UAT

Business/Security gate

Run user/entitlement test scenarios
PROD

Required reviewer + concurrency safety + post-deploy verification
Build once, merge per environment. The approved RLS role TMDL stays unchanged through DEV → TEST → UAT → PROD. For each environment the pipeline retrieves that environment's current live semantic-model definition and merges the approved role into it.
